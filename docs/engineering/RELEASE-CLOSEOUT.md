# Reviewable foundation closeout

11 October 2026. The user authorized foundation implementation, commercial-plan corrections, release preparation and RTOS engineering. The implementation author is Codex; this is not represented as human review.

## Prepared controls

- Default SDK evaluation uses the installed pinned context; legacy raw evaluation requires explicit opt-in. Canonical verifier algorithms and signed wire profiles remain unchanged.
- `rtos/` provides the bounded C gate, FreeRTOS adapter, adversarial tests and a canonical native V3 bridge. Hardware isolation/timing/safety are commissioning gates.
- Per-path mapping explicitly retains MPL-2.0 for SDK and enforcement; Apache-2.0 for protocols/docs/governance. Existing public rights are preserved.
- Contributor-rights workflow reads only trusted base code and publishes a head-bound status. The CLA remains draft with zero acceptances until the conditions in PR #12 are resolved.
- `Publish verified preview` is a manual workflow. It requires public/protected exact main, a merged PR with independent human approval of its exact head, successful latest **push-to-main** workflows with required jobs/steps actually executed, and an immutable preview tag. Same-SHA interrupted publication can recover; other tags are never replaced.

## Remaining release sequence

1. Inspect final candidate CI and native conformance, including step outcomes and artifact/source pins.
2. Record human technical delta review of the final source and configuration. A prior review of older commits is retained as history, not substituted.
3. Merge reviewed changes through existing branch controls; do not force-update protected `main`.
4. Verify exact post-merge main CI and the pinned Halibut integration against the resulting SWOOSH commit. A passing branch run is not a passing main run.
5. For Halibut, apply its prepared main ruleset, then complete the owner-approved visibility change only after the existing release gates are satisfied.
6. Run `Publish verified preview` on `main`, supplying the reviewed merged PR number. The workflow performs the tag/release operation only after validating its gates.

The current connector exposes code/PR operations but no repository administration, visibility mutation or release-creation endpoint. The ruleset and release workflow make those operations concrete; they are not claimed applied merely because their files exist. Human approval and legal signatures cannot be generated by this implementation.

The existing `RELEASE_CHECKLIST.md` remains the release authority. This file adds evidence-producing controls; it does not remove its human technical-review requirement. Customer isolation, persistent anti-rollback stores, production signing, independently anchored audit and physical safety are outside the tested reference foundation and need scoped commissioning.
